# Native Git parity ledger

Native files-backend compatibility remains partial. A checksum-protected
finalization receipt ties intended refs/index state to owned lock markers
across journal cleanup and process death. It refuses unknown lock owners and
divergent state. It does not provide crash atomicity, authorize arbitrary
stale-lock deletion or exclude privileged or uncooperative filesystem writers.
The table below tracks all 94 gaps.

## Baseline and test profiles

- Oracle: Git 2.47.3, selected by `GIT_ORACLE_BINARY` (default: `git` on
  `PATH`; the oracle refuses any other version). Crystal 1.21.0, Linux
  x86-64. Do not extrapolate to other Git versions or platforms. See
  [ORACLE_FIXTURES.md](ORACLE_FIXTURES.md).
- `SHA1-files-index`: files refs, SHA-1 object format, index v2/v3/v4
  bounded fixtures.
- `SHA256-files-index`: files refs, SHA-256 object format, real
  Git-generated loose/packed objects (including REF_DELTA), index v2/v3/v4,
  and malformed/corrupt negatives.
- `reftable`, `split/sparse index`, full multi-worktree inventory,
  `macOS/Windows`, and Git versions other than 2.47.3 are
  **unverified/unsupported**. Non-UTF-8 Linux Git index/tree/ref bytes are
  oracle-tested; the agent path still admits UTF-8 only.
- Work statuses are `not-started`, `in-progress`, `blocked` or `done`.
  Library statuses are `native-oracle-verified`, `native-partial`,
  `external-provider-required`, `unsupported`, or `unverified`. Each status
  applies only to the named profile.
- Each of the 94 gaps keeps its assigned primary task. When fixture failures
  reveal a new gap, give it a new identifier.
